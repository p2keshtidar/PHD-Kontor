## 🔁 Ablauf eines Sprints (2 Wochen)

```
 Mo           Do           Mo           Do           Fr
 ┌──────────┐ ┌─────────┐  ┌─────────┐  ┌─────────┐  ┌──────────────────┐
 │ Planning │ │Stand-up │  │Stand-up │  │Stand-up │  │ Review + Retro   │
 │  60 Min  │ │ 15 Min  │  │ 15 Min  │  │ 15 Min  │  │  45 + 30 Min     │
 └──────────┘ └─────────┘  └─────────┘  └─────────┘  └──────────────────┘
```

| Meeting | Wann | Dauer | Ergebnis |
|---|---|---|---|
| **Sprint Planning** | 1. Tag des Sprints | 60 Min. | Sprintziel + Aufgaben (Issues im Milestone) |
| **Stand-up** | Mo + Do | 15 Min. | Wer macht was, wo hängt es? |
| **Sprint Review** | letzter Freitag | 45 Min. | Demo der fertigen Funktionen |
| **Retrospektive** | nach dem Review | 30 Min. | Was verbessern wir? (Start/Stop/Continue) |

## ✅ Definition of Done

Eine Aufgabe ist **fertig**, wenn:

- [ ] der Code über einen **Pull Request** in `main` ist und **ein anderes Teammitglied** ihn reviewt hat
- [ ] alle **automatischen Prüfungen (CI) grün** sind
- [ ] es für neue Logik mindestens **einen Test** gibt
- [ ] die Funktion auf **mindestens einem Handy** (Android oder iPhone) und im **Browser** ausprobiert wurde
- [ ] Anleitung/Pflichtenheft angepasst sind, falls sich etwas Sichtbares geändert hat
- [ ] das Issue geschlossen ist

## ✍️ Protokoll schreiben – so geht's

1. Datei des Meetings öffnen (z. B. `sprint-01/standups.md`).
2. Auf GitHub oben rechts auf ✏️ **Edit** klicken.
3. Die 📝-Stellen ausfüllen.
4. Unten **Commit changes** → Nachricht z. B. `Scrum: Stand-up 15.10.` → fertig.
